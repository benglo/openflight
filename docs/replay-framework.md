# Replay Framework

A regression / A-B testing harness for the rolling buffer signal pipeline.
Replays captured session JSONL files through the live processor and produces
structured diffs.

## Why

Iterating on signal-processing changes (spin detection, CFAR thresholds,
ball/club separation) without a hardware-in-the-loop feedback cycle. The
framework consumes session captures recorded during real swings, re-runs the
processor offline, and reports detection-rate and accuracy deltas vs the
originally logged shots.

Once a corpus of session captures is collected, the resulting JSON reports
also feed downstream consumers — most notably the planned ballistic carry
model, which needs measured-vs-modelled paired data.

## Usage

Single session:

```bash
uv run python scripts/analysis/replay_session.py \
    ~/openflight_sessions/session_2026-04-27.jsonl --output report.json
```

A whole directory (all `session_*.jsonl` files):

```bash
uv run python scripts/analysis/replay_session.py ~/openflight_sessions --summary
```

With a config override (recorded in the report fingerprint):

```bash
uv run python scripts/analysis/replay_session.py \
    ~/openflight_sessions/session_X.jsonl \
    --processor-config experiments/dc_mask_200.json \
    --output report.json
```

## Output schema (v1)

```json
{
  "schema_version": 1,
  "processor_config": {
    "sample_rate": 30000,
    "window_size": 128,
    "fft_size": 4096,
    "step_size_overlap": 32,
    "dc_mask_bins": 150,
    "magnitude_threshold": 3,
    "spin_bandpass_bw_hz": 700,
    "spin_snr_high": 8.0,
    "spin_snr_medium": 5.0,
    "spin_snr_min": 3.0
  },
  "sessions": [
    {
      "source_path": "session_X.jsonl",
      "captures": [
        {
          "shot_number": 1,
          "capture_line": 42,
          "original": { "ball_speed_mph": 145.2, "spin_rpm": 2510, "...": "..." },
          "replayed": { "ball_speed_mph": 145.0, "spin_rpm": 2480, "...": "..." },
          "regression": false,
          "new_detection": false
        }
      ],
      "stats": {
        "total_captures": 0,
        "replay_detection_count": 0,
        "ball_speed_mae_mph": 0.0,
        "spin_mae_rpm": 0.0,
        "regressions": 0,
        "new_detections": 0
      }
    }
  ],
  "aggregate": { "total_captures": 0, "regressions": 0, "...": "..." }
}
```

`processor_config` is the algorithm fingerprint — comparing two reports
generated by different code revisions begins by checking these values match.

`regression` flags a capture that the original code detected but the replay
no longer detects. `new_detection` flags the inverse — captures that the
original missed but the new code now picks up.

MAE values in `stats` are computed only over captures where the relevant
field is present in both `original` and `replayed`. Batch-level MAE in
`aggregate` is **count-weighted**, not session-weighted, so a session with
1 comparison contributes less than a session with 30.

## Distinction from `replay_captures.py`

- `scripts/analysis/replay_captures.py` — per-capture FFT-level debugger.
  Prints human-readable spectrum analysis for a single capture. Use when
  investigating one specific shot.
- `scripts/analysis/replay_session.py` — corpus-level harness. Produces
  machine-readable diff reports across many captures. Use when evaluating
  algorithm changes against a saved corpus.

## Limitations (v1)

- `--processor-config` overrides are **recorded** in the report fingerprint
  but not yet **applied** to the live processor — its constants are class-
  level rather than instance-configurable. Honest A-B testing today still
  requires editing `RollingBufferProcessor` constants between runs.
  Wiring full instance-level config is a follow-up refactor.
- Only `rolling_buffer_capture` and `shot_detected` entries are replayed.
  K-LD7 (`iq_blocks`, RADC frames) and camera launch-angle data are not yet
  part of the comparison.
